# Протокол

Клиент ничего не решает: он рисует присланное состояние и отправляет
намерения. Все проверки правил — на сервере.

Транспорт: **POST для действий + SSE для состояния**. WebSocket для пошаговой
игры избыточен, а `EventSource` переподключается сам и проще проходит через
прокси. Если когда-нибудь понадобится двусторонний канал (чат голосом,
анимации в реальном времени), менять придётся только `internal/httpapi`.

## Ручки

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/api/rooms` | создать комнату |
| `POST` | `/api/rooms/{id}/join` | войти в комнату |
| `GET` | `/api/rooms/{id}/events?token=…` | поток состояний (SSE) |
| `GET` | `/api/rooms/{id}/state?token=…` | состояние одним запросом |
| `POST` | `/api/rooms/{id}/action` | действие в партии |
| `POST` | `/api/rooms/{id}/leave` | выйти из комнаты |
| `POST` | `/api/rooms/{id}/bot` | посадить бота, убрать его, сменить уровень, отдать боту место ушедшего |
| `POST` | `/api/rooms/{id}/chat` | реплика в чат комнаты |
| `POST` | `/api/rooms/{id}/voice` | войти в голосовой звонок или выйти |
| `POST` | `/api/rooms/{id}/signal` | переложить сигнал WebRTC соседу |
| `GET` | `/api/meta` | неизменные данные: карта, характеристики, умения |
| `GET` | `/healthz`, `/readyz`, `/version` | служебные |

### Создание комнаты

```jsonc
POST /api/rooms
{ "mode": "online", "name": "Аня" }                       // три экрана
{ "mode": "hotseat", "names": ["Аня", "Боря", "Витя"] }    // один экран
{ "mode": "hotseat", "names": ["", "Аня", ""],             // один против двух ботов
  "bots": ["hard", "", "normal"] }
{ "mode": "hotseat", "names": ["Аня", "Боря", "Витя"],     // на второй карте
  "map": "split" }
```

Ответ: `{ "room": "K4M7Q", "mode": "online", "token": "…", "seat": 0, "name": "Аня" }`

`bots` — только для hotseat: уровень бота для каждого места (`easy`,
`normal`, `hard`), пустая строка — за местом человек. Боту можно не давать
имени: сервер возьмёт свободное из трёх домов лора. В ответе `seat` и `name` —
первого человеческого места.

`map` — карта комнаты: `classic` («Теснина», по умолчанию) или `split`
(«Разделённый замок»). Неизвестный ключ молча читается как `classic`:
партия должна начаться даже с кривым запросом. Сменить карту после создания
нельзя — это другая партия.

`token` — секрет игрока. Клиент хранит его в `localStorage` и шлёт в каждом
действии; по нему же работает возврат в партию после перезагрузки.

### Действие

```jsonc
POST /api/rooms/K4M7Q/action
{
  "token": "…",
  "action": { "kind": "move", "unitId": 7, "to": { "x": 6, "y": 3 } }
}
```

Виды действий:

| `kind` | Поля | Смысл |
|---|---|---|
| `move` | `unitId`, `to` | перемещение |
| `attack` | `unitId`, `to` | удар по юниту или сегменту стены |
| `deploy` | `unit`, `to` | наём в своей зоне |
| `climb` | `unitId` | любой пеший отряд лезет по соседней лестнице |
| `charge` | `unitId`, `to` | подрывник закладывает заряд под выбранный соседний сегмент: пролом сразу, сам он гибнет |
| `board` | `unitId`, `to` | пеший отряд садится в свою осадную башню на клетке `to` |
| `ramp` | `unitId` | осадная башня опускает трап; только вплотную к стене |
| `unload` | `unitId` (пассажир), `to` | пассажир сходит по трапу на боевой ход |
| `ability` | `ability` (`pitch`/`rebuild`/`gate`), `at` | умение замка; сегмент адресуется клеткой `at`. На «Теснине» принимается и старое `col` — номер столбца; на карте с кольцом стены столбца мало, и там только `at`. `rebuild` ограничен двумя за ход |
| `ability` | `ability: "militia"` | только замок: трое горожан у короля, раз в ход. Клетку выбирать не надо |
| `ability` | `ability: "rally"` | воодушевление: ×2 урона до конца хода, доступно всем |
| `build` | `unitId`, `build` (`trap`/`barricade`/`repair`/`watchpost`), `to` | работа инженеров; `repair` — только по своим постройкам; `watchpost` ставят инженеры замка и пехота осаждающих |
| `build` | `unitId`, `build: "outpost"`, `to` | осаждающий разбивает аванпост (2 ОД) |
| `construct` | `build` (`barracks`/`arrowTower`/`forge`), `to` | замок строит во дворе (2 ОД) |
| `heal` | `unitId`, `to` | лекарь лечит соседний свой отряд |
| `endTurn` | — | завершить ход |

Успех — `204 No Content`. Ошибка — JSON `{"error": "…"}` с понятным текстом:
`409` — не ваш ход, `401` — чужой токен, `404` — нет комнаты, `400` — всё
остальное (нельзя так ходить, не хватает припасов).

### Выход из комнаты

```jsonc
POST /api/rooms/K4M7Q/leave
{ "token": "…" }
```

Ответ — `{"freed": true}`, если место освободилось совсем (партия ещё не
началась или это hotseat), и `{"freed": false}`, если осада уже идёт: тогда
место остаётся за игроком, но он помечается ушедшим (`left` в списке
игроков), поток событий обрывается, а звонок с этого места закрывается.
Клиент в обоих случаях забывает токен.

### Боты

```jsonc
POST /api/rooms/K4M7Q/bot
{ "token": "…", "op": "add", "level": "normal" }            // лобби: бот на свободное место
{ "token": "…", "op": "remove", "seat": 2 }                 // лобби: убрать бота
{ "token": "…", "op": "level", "seat": 2, "level": "hard" } // сменить уровень, и посреди партии тоже
{ "token": "…", "op": "replace", "seat": 1, "level": "easy" } // партия: место ушедшего — боту
```

Управлять ботами может любой человек в комнате. Бот занимает место так же,
как игрок: с третьим занятым местом партия начинается сама. `replace`
работает, только если игрок на этом месте вышел из партии или не на связи;
место уходит боту насовсем, и токен ушедшего перестаёт действовать. Убрать
бота из начатой партии нельзя — играть за его место было бы некому.

В снимке боты лежат в том же списке `players`, что и люди, с полем `bot` —
уровнем; бот всегда `online`. Уровни с подписями и описанием приезжают в
`/api/meta` полем `botLevels` (`key`, `label`, `title`, `hint`).

Ходит бот на сервере, в своей горутине, по одному действию: каждое уходит в
поток снимков, как ход живого соперника. Если ход бота меняет то, что видят
люди у экранов, между действиями выдерживается пауза `SIEGE_BOT_DELAY`
(по умолчанию 350 мс), чтобы ход можно было разглядеть; ходы в тумане
проходят без пауз. На вход бот получает ровно тот снимок, что ушёл бы
человеку на его месте, — туман войны, засады и чужие ловушки вырезаны из
него так же — и проверяет его действия тот же `game.Apply`.

### Чат

```jsonc
POST /api/rooms/K4M7Q/chat
{ "token": "…", "text": "ломаю левую башню", "channel": "siege" }
```

`channel` — `all` (по умолчанию) или `siege`. Осадный канал слышат только
двое осаждающих: писать в него может лишь осаждающий, а в чужой снимок его
реплики не попадают вовсе. Поле `siege` в снимке говорит клиенту, показывать
ли переключатель каналов.

Имя автора сервер подставляет сам по токену — подписаться чужим именем
нельзя. Управляющие символы вырезаются, длина режется до 200 символов,
история хранится последними 60 репликами и живёт столько же, сколько
комната. Сообщения приезжают в том же снимке, что и состояние партии, полем
`chat`.

### Голосовые звонки

Звук идёт напрямую между браузерами; сервер работает телефонисткой.

```jsonc
POST /api/rooms/K4M7Q/voice
{ "token": "…", "active": true }        // я в звонке; места видны всем в snapshot.voice

POST /api/rooms/K4M7Q/signal
{ "token": "…", "to": 1, "data": { … } } // data — непрозрачный блок SDP/ICE
```

Содержимое `data` сервер **не разбирает**: проверяет отправителя по токену,
что получатель — другое место в этой же комнате, и кладёт в его поток SSE
событие `signal` с конвертом `{from, name, data}`. Для сигналов действует
отдельный лимит частоты: установка звонка — это несколько сообщений подряд.

Кто кому звонит, решает правило «инициирует младшее место»: иначе оба
собеседника пришлют по offer'у и соединение не соберётся.

Формат `data` — дело клиентов (`web/voice.js`), сервер его не проверяет:

```jsonc
{ "sid": "k3f9q2ab", "signals": [ { "type": "offer", "sdp": "…" }, { "type": "candidate", … } ] }
{ "hello": true, "sid": "k3f9q2ab" }   // старшее место просит младшее перезвонить
```

- Кандидаты ICE уходят по мере сбора (trickle): offer летит сразу, не дожидаясь
  полного сбора, который за VPN или при недоступном STUN тянется секундами.
  Пока летит один запрос, следующие сигналы копятся и уходят одним пакетом —
  на соединение выходит три-четыре запроса, а не десяток.
- `sid` — номер попытки соединения. Сигналы чужой попытки отбрасываются,
  а offer с новым `sid` заменяет прежнее соединение с этим местом.
- Не собралось за 12 секунд или оборвалось — младшее место перезванивает само
  с паузой 1, 2, 4… до 15 секунд. Старшее, потеряв связь, шлёт `hello` с
  последним виденным `sid`, чтобы перезвонили сразу.
- Если поток SSE оборвался, сервер вычёркивает игрока из `snapshot.voice`;
  клиент, который всё ещё в звонке, заметит это по снимку и повторит
  `POST /voice`.

Список серверов ICE приезжает в `/api/meta` полем `iceServers` в формате
`RTCConfiguration` и задаётся переменной `SIEGE_ICE_SERVERS`.

### Поток состояний

```
GET /api/rooms/K4M7Q/events?token=…

event: state
data: {"room":"K4M7Q","phase":"play","game":{…}}

event: signal
data: {"from":0,"name":"Аня","data":{…}}
```

Каждое событие — **полный снимок**, а не дельта: партия маленькая, зато
переподключение не требует синхронизации. Раз в 20 секунд уходит
комментарий-пинг, чтобы прокси не рвал соединение.

Поля `map` и `mapName` — на какой карте комната; они приходят и в лобби,
до начала партии, чтобы игроки видели, на что садятся. Геометрию этой карты
клиент берёт из `/api/meta`: там лежит `boards` — по записи на карту, с
размером, клетками (`tiles`), рудниками, пашнями и клетками для смолы.
Сегменты стены в снимке адресуются клеткой (`wall[].pos`), а не столбцом:
на «Разделённом замке» кладка — кольцо, и в одном столбце её сегментов
несколько.

Поле `phase` — где сейчас комната: `lobby` (ждём игроков), `play` (осада
идёт) или `over` (король пал либо замок выстоял). Партия — **одна осада**,
следующей за ней нет: в `over` приезжает `game.result` (`captured`,
`capturedBy`, `days`, `summary` с именем победителя), а очки — в
`game.seats[].score`; после итогов садятся за новую партию в новой комнате.
Роли закреплены за местами: кто за кого играет, говорит поле `seatSides` в
`/api/meta` (`["defender", "attackerA", "attackerB"]`), и лобби подписывает
игроков по нему ещё до начала.

## Скрытая информация

Снимок собирается **для конкретного игрока** в
[internal/game/view.go](../internal/game/view.go). Скрытое не «приходит со
скрытым флагом», а не попадает в снимок вообще: отряд в засаде отсутствует в
`units` противника, а поле `traps` содержит только свои ловушки.

**Туман войны** работает там же: чужой отряд попадает в `units`, только пока
его просматривают свои отряды, постройки или удерживаемая башня. Маска
видимости приезжает полем `fog` — по строке на ряд карты, `'1'` видно,
`'0'` туман; клиент по ней затемняет клетки. Хроники в снимке нет вовсе:
единственное укрытие — туман, и то, чего игрок не видит, до него просто не
доезжает.

То же правило и у **построек**: чужой частокол, вышка или аванпост попадают
в `buildings`, только пока их клетку кто-то просматривает. Своё и союзное по
осаде видно всегда — постройка светит себе сама. Исключение одно: ничейный
мост у ворот, он стоит на карте с первого дня и приезжает всем.

Подсмотреть ход соперника в сетевом трафике нельзя.

В снимке своим юнитам сервер заодно присылает список допустимых клеток
(`moves`, `targets`, `zone`, `buildAt`, `fixAt`, `outpostAt`, `healAt`,
`gateAt`, `fascineAt`, `storeAt`, `mantletAt`) — это и подсветка в интерфейсе, и
единственный источник истины о том, что разрешено. Правила рельефа учтены и
там: обрыв не попадёт в `moves`, а клетка, где уже стоит частокол, — ни в
`moves`, ни в `buildAt`. Колёсная машина не получит в `moves` открытую
клетку рва, зато получит засыпанную.

Особняком стоит `fenceAt` у инженеров замка: это не список клеток, а список
**прясел** частокола — по линии на каждую клетку из `buildAt`, первой точкой
сама клетка. Одно действие ставит всю линию (три клетки поперёк направления
«инженер → цель»), и считает её сервер: крайние колья лежат в двух клетках
от инженера, и годность этих клеток клиенту знать не откуда. Клиент рисует
по ним призрак линии под курсором, а серверу присылает, как и раньше, одну
клетку в `to`.

Состояние укреплений открыто всем: каждый сегмент в `wall` приезжает с
`kind` (`wall`, `gate`, `tower`, `woodgate`), `hp`/`maxHp` и `open` —
поднята ли решётка. Поле `moat` снимка перечисляет **незасыпанные** клетки рва: засыпанных в нём
нет, потому что они уже работают как поле. Сам настил приезжает в
`buildings` постройкой вида `fascine` — со своей прочностью и хозяином, её и
бьют, чтобы вернуть воду. Список `moat` считается **по видимым** настилам:
чужая вязанка в тумане воду в снимке не закрывает, иначе её выдавал бы цвет
клетки — прятать саму постройку тогда не имело бы смысла. Список построек, доступных инженерам, в
`/api/meta` разделён надвое: `builds` — для замка, `sapperBuilds` — для
полевых инженеров осады. Потолок
обоза приходит в `you.supplyCap`, звёзды ветерана — полем `stars` в записи
отряда, и видны они всем: как бьёт выращенный отряд, противник всё равно
узнает.

Осадная башня приезжает с `capacity` и `ramp` — вместимость и опущен ли
трап, это видят все. А вот `cargo` (список пассажиров: id, тип, здоровье,
ходил ли уже) приходит **только её хозяину**: противник не знает, пуста башня
или полна. Самих пассажиров в `units` нет вовсе — на карте их не существует,
пока они внутри. Своему хозяину башня отдаёт ещё `canRamp`, `unloadAt`
(куда сходят по трапу, на боевой ход) и `exitAt` (куда можно вылезти без
трапа, на землю рядом), а отряды рядом с ней — `boardAt`.

Короля видно по флагам `royal` и `meleeOnly` в его записи в `units`: клиент
рисует его отдельно и знает, что издали по нему не прицелиться. У подрывника
есть `charges` (сколько зарядов осталось) и `chargeAt` — список соседних
сегментов, под которые заряд можно заложить прямо сейчас.

Клетки, куда замок может плеснуть смолой, лежат в мете полем `pitchTiles`:
у ворот это сама клетка ворот, у остальных столбцов — ряд под стеной. Сервер
всё равно принимает только номер столбца и ставит центр сам.

Маска `fog` у осаждающего считается по отрядам и постройкам **обоих**
осаждающих сразу: по правилам осады они союзники и делят разведку. У замка
маска только своя.

Зона найма `zone` у осаждающего включает не только лагерь, но и клетки вокруг
его аванпоста, пока тот стоит. У замка в `you` приезжают `court` (свободные
клетки двора) и `courtBuilds` (что можно построить, с ценой и пределом), а
также `rebuild` — во сколько припасов обойдётся отстройка пролома: кузница
эту цифру сбивает. Поля `you.rally` и `you.rallyOk`
говорят, действует ли воодушевление и можно ли его прочитать прямо сейчас,
а `you.militiaOk` — доступно ли ополчение. У умений в мете есть флаг
`instant`: такие срабатывают сразу, без выбора клетки на карте. У временных построек в `buildings` есть поле
`life` — сколько дней осталось до сворачивания. В `buyable` у отрядов с
пределом (катапульты) приезжают `have` и `max`: сколько уже на поле и сколько
можно держать.

Цена в `buyable` и `courtBuilds` приезжает во всех валютах сразу: `cost` —
припасы, `silver` — серебро, `ap` — очки действия. Если позиция сейчас
недоступна, `affordable` ложно, а `why` говорит почему: `max` (предел таких
отрядов или построек), `army` (предел армии), `hires` (наём на этот ход
исчерпан), `court` (во дворе нет свободной клетки), `ap`, `silver` или
`supplies` (не хватает очков, серебра или припасов). Коды перечислены в
порядке важности: если наём исчерпан, `supplies` не придёт, даже когда
припасов тоже мало. Те же коды и ещё два — `used` (уже созывали в этом ходу)
и `room` (у короля негде встать) — приезжают замку в `you.militiaWhy`. У
умений в мете поле `ap` — цена в очках действия; если его нет, умение стоит
одно очко.

Доход приезжает прогнозом: `you.income` — сколько припасов придёт в начале
следующего хода, `you.incomeParts` — из чего это число складывается (список
`{label, amount}`: обоз, казармы, пашни, вышки), `you.silverIncome` — серебро
с рудника. Начисление на смене хода считает та же функция, поэтому прогноз
сбывается, пока расклад на поле не изменился: казармы могут разбить, с пашни
и рудника — согнать. Остаток очков действия в конце хода превращается в
припасы отдельно, по `apCarry` из меты, и в прогноз не входит.

Описания клеток и построек для карточки осмотра и строки под полем лежат в
мете: `terrain` — по символу из `tiles` (плюс `woodgate` и `breach` для
сегментов стены, сменивших вид по ходу партии), `structures` — по `kind`
постройки. У каждого описания `label`, `short` (пара слов для строки) и
`hint` (правило целиком); числа в них подставляет сервер из правил. Свои
отряды в свой ход приезжают ещё с флагами `moved` и `acted` — уже ходил и уже
действовал (бил, строил, лечил), — а умеющие кидать фашины ещё и с
`fascineAp`: во что им это встанет, у пехоты поля нет — ей даром. Чужим эти
флаги не уходят.

Пределы на ход приезжают в `you` парами: `fixes`/`fixesMax` — сколько ремонтов
стены осталось в этом ходу (счёт общий на умение замка и на инженеров), и
`hires`/`hiresMax` — сколько отрядов ещё можно нанять. У замка там же лежит
`king` — здоровье и положение собственного короля: приз осады — единственная
фигура, за которой приходится следить отдельно от всей армии.

Доходные клетки приезжают двумя списками той же формы: `mine` (рудник, включая
клетку в углу двора) и `farm` (пашни по флангам). У каждой — чья она сейчас,
причём чужой отряд на ней виден только через свой обзор.

Отряд, затаившийся в кустах, в чужой снимок не попадает вовсе. Своему хозяину
он приезжает с флагом `lurking`: по нему видно, что засада ещё не раскрыта и
первый удар пойдёт с утроенным уроном.

У наблюдательных пунктов в `buildings` есть поле `hold` — чей он сейчас
(`neutral`, если оспорен). Счётчик удержанных лежит в `you.towers`, а цена,
предел и уже построенное — в `you.watch`, `you.watchMax` и `you.watchHad`:
у сторон цена разная. У отрядов, которые умеют их ставить, приезжают `canWatch`
и `watchAt`.

Поле `reach` у каждого юнита — его дальность с учётом бонуса от башен. По нему
клиент рисует зоны обстрела, не запрашивая ничего дополнительно: кто куда
достаёт — открытая информация, в отличие от ловушек и засад. Поле `area`
означает навесное оружие: такой отряд бьёт по клетке в пределах `reach`, и
список `targets` ему не нужен — целиться можно и в туман.

Все списки в снимке приходят непустыми (`[]`, а не `null`): иначе клиент,
которому туман скрыл всё до последнего отряда, спотыкался бы на первом же
обращении к списку.

## Режим hotseat

Один токен владеет всеми тремя местами, а «своим» считается то, чей сейчас
ход (`seatForLocked` в [internal/room/room.go](../internal/room/room.go)).
Поэтому скрытая информация показывается тому, кто сидит за экраном прямо
сейчас, — как в настольной игре, где карты держат в руках по очереди.

Места, отданные ботам, этот токен не играет. Пока ходит бот, экран
показывает следующего по очереди человека: он уже сел к экрану и смотрит
ход бота своими глазами, а не глазами бота. Если людей нет вовсе (все три
места у ботов), экран смотрит как наблюдатель — ему видно всё поле.
